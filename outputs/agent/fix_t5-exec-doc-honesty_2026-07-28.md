## 1. What the first pass missed, and why that was structural

Commit `ac018fb` correctly removed the worst sentence — *"KoFIU (AML) — large/suspicious
transactions are detected and filed (CTR/STR)"* — from `outputs/docgen/build.js` and regenerated
the `.docx`.

It did not touch `outputs/feature_spec_artifact.html`, **because that file was not generated by
`build.js` at all.** It was a second, hand-authored rendering of the same document. So after the
fix, the Word file said the honest thing and the pretty web artifact — the one that actually gets
shown to people — still said:

- *"Reporting & Compliance — BOK FX reports, **KoFIU AML (CTR/STR)**, Hometax tax invoices"*
- *"KYB Adapter — **Business screening** & registration verification during onboarding"*
- *"Verify (KYB). … **the verdict is stored**"* (no mention that nothing screened it)
- *"**Ship files & announce.** Generate scheme settlement files; emit 'settlement completed'"*
- *"Partner notifications — **signed webhooks**, retry with back-off, dead-letter + alert"*
- *"Regulatory reporting — BOK FX …, **KoFIU CTR/STR**, monthly Hometax invoices"*
- *"Portals — … **partner self-service**"*

**That is the actual bug class, and it is not "someone forgot".** Two hand-authored renderings of
one document guarantee that a correction applied to one of them decays in the other. Editorial
care cannot fix a structure that requires the same edit in two places, and a document whose claims
are *restated* from code has no way to notice when the code stops matching.

So the fix is three structural changes, then the content corrections.

## 2. Structural change 1 — one content model, two renderings

```
outputs/docgen/
  truth.js         derives facts: parses GAP_REGISTER.md, reads the platform's status vocabularies
  content.js       THE content model — one array of sections, cited claim by claim
  render-docx.js   → outputs/GMEPay+_Feature_Specification.docx
  render-html.js   → outputs/feature_spec_artifact.html
  build.js         entry point; writes BOTH, or --check verifies both are up to date
```

`build.js` resolves its output paths from `__dirname`, not the process working directory (the old
version wrote to `../GMEPay+_Feature_Specification.docx`, so it produced a file in a different
place depending on where you ran it). The rendered artifacts are now build outputs, and both say
so in their own footer: *"generated … do not hand-edit"*.

## 3. Structural change 2 — every claim is pinned to the register

`content.js` opens with **42 `assertGap(id, state)` calls**. Each one is the justification for the
sentence(s) that cite it, and each one fails the build if the register marker moves:

```
DRIFT: gap T5-2 is now CLOSED in GAP_REGISTER.md (line 139) but the specification's
wording assumes PARTIAL.
  T5-2: Regulatory lanes fabricate "ACCEPTED"; nothing has ever been filed …
  Re-read the claim that cites it in content.js and correct the WORDING, then update
  this assertion. Do not relax the assertion to make the build pass.
```

This cuts both ways deliberately. It stops the document drifting back into overstatement, **and**
it stops it rotting into stale pessimism after work lands — a document that still says "no
transaction has ever been screened" a year after screening ships is also lying.

The honest status words the document prints are read out of the platform's own source, not
retyped:

| `NOT_FILED_CHANNEL_UNAVAILABLE` | `services/reporting-compliance/.../channel/FilingChannelStatus.java` |
| `NOT_TRANSMITTED_CHANNEL_UNAVAILABLE` | `services/settlement-reconciliation/.../transmission/SettlementTransmissionState.java` |
| `NO_PROVIDER_ID` | `libs/lib-kyb/.../ScreeningProvenance.java` |

| "Green means transmitted, and nothing else." | `apps/admin-ui/src/api/settlementStatus.js` |

A rename of any of those fails the build rather than printing a word the platform has retired.

## 4. Structural change 3 — the success state is unreachable

Every capability now carries a state, and the vocabulary is deliberately shaped like admin-ui's
`filingStatus.js` — one place decides the wording, and the success value is reserved:

| State | Means exactly |
|---|---|
| `LIVE` | exercised against the real external counterparty in a standing environment |
| `BUILT · LOCAL ONLY` | built, exercised only against simulators and tests |
| `BUILT · NOT LIVE` | built and refusing on purpose until a named external gate opens |
| `PARTLY BUILT` | some of it exists; what is missing is named |
| `NOT BUILT` | there is no code for it |
| `BLOCKED ON A DECISION` | deliberately unbuilt until a named owner decides |

`assertNothingClaimsLive()` **refuses to build if anything claims `LIVE` while T1-6 (no always-on
environment) is open** — nothing can be live where nothing is running. That is the same move as
admin-ui reserving a success colour for a real filing: the honest state is enforced by the
generator, not by whoever edits the prose next.

## 7. Determinism (task 5 / VERIFY)

Both artifacts regenerate byte-identically. Two problems had to be fixed to get there, because a
committed artifact that changes on every build cannot be diffed and makes "is the checked-in file
current?" unanswerable:

1. **Zip entry timestamps.** A `.docx` is a zip and every entry was stamped with the wall clock.
   `withFixedTimestamps()` repacks with one pinned instant per entry.
2. **`docProps/core.xml`.** This version of the `docx` library **ignores** the `created`/`modified`
   document options and writes `new Date()` anyway; those two elements are rewritten. If the
   library changes that format, the rewrite matches nothing and the build **throws** rather than
   silently going non-deterministic again.

```
docx run1 = EAC52735…550F9      html run1 = BFF59EBF…F4B0
docx run2 = EAC52735…550F9      html run2 = BFF59EBF…F4B0
docx deterministic: True        html deterministic: True
node outputs/docgen/build.js --check  →  OK — both rendered artifacts match the generator.
```

`--check` is the guard worth wiring into CI later (`npm --prefix outputs/docgen run check`); it is
**not** wired in here, because CI configuration is `scripts/**`/workflow territory that this
change does not own. **Listed, not done.**
